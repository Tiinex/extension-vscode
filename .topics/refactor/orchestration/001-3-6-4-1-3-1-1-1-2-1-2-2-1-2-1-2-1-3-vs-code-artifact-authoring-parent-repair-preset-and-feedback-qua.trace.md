# VS Code Artifact Authoring Parent, Repair, Preset And Feedback Qualification

## Supported Claim Or Question

- Supported Claim Or Question: does the current VS Code host make generic Tiinex artifact authoring practical without inventing editor-owned schema semantics, specifically for bounded Parent discovery, continuation from qualified historical debt, deterministic repair, Preview/Create behavior, Handoff presets, and Feedback capability failure
- Evidence Role: qualify the bounded Core + extension-vscode correction against Sigma's observed live-host failures

## Provenance

- Known Source: `tiinex-vscode-extension-001` pointerless Core + extension-vscode source frontier plus Sigma's live-host screenshots of Parent selection, slow authoring startup, parent-blocked continuation, Preview/Create confirmation flow, malformed historical references, Handoff preset behavior, and Feedback creation failure
- Preservation Basis: exact local Core and extension-vscode source changes, focused Core regressions, full Core test suite, full VS Code bridge suite, and package integration qualification
- Provenance Limits: Windows live-host visual acceptance remains Sigma-owned; this Evidence does not claim Feedback artifact creation where Core currently exposes no qualified creation renderer
- Semantic Authority Boundary: Core remains the authoring/validation/repair authority; VS Code only scopes discovery, presents qualified contracts, and invokes deterministic Core operations

## Evidence Material

- Material: Core authoring Parent projection and editor assistance plus VS Code generic artifact authoring host flow
- Material Kind: bounded implementation and deterministic local qualification
- Parent Picker: Parent selection is staged as `No Parent | Workspace` -> `Leaves | Full lineage` -> searchable newest-modified-first candidates from that one Workspace; Leaves uses Core's `loaded-leaf-candidate` projection and no longer performs a second full Markdown Workspace indexing pass merely to build the picker
- Parent Startup: Local Workspace choices are short-lived cached within the authoring flow; authoring model loading and Parent qualification execute in parallel; the qualified Parent record is retained on the draft context so Preview/Create do not repeat Parent qualification
- Historical Parent Debt: exact verified Parent bytes carrying only malformed historical Workspace-qualified ancestor recovery locators may continue fail-bounded with `portable.authoring-parent.historical-ancestor-recovery-debt`; the child does not inherit, repair, or upgrade that ancestor debt
- Parent Repair: shared Core editor assistance can normalize deterministically malformed `../../workspace::path` recovery references and a bare Current Schema id when exact schema authority is independently qualified, reseal c14n-v2 self integrity, and expose the replacement only when shared audit/lineage guardrails re-qualify it
- Descendant Safety: Core intentionally withholds a single-file historical-reference replacement when loaded digest-bound descendants would be invalidated; VS Code does not offer a destructive fake repair in that case
- Preview/Create: Preview only materializes and opens virtual preview bytes; it does not ask the user to create. Create writes the exact Core-qualified draft directly, refreshes the operator state, and closes the authoring panel after success
- Handoff Presets: the Handoff presentation retains Core-owned required sections while `Perform bounded work` and `Discuss / review` presets deterministically prefill Purpose, Transfers, no-context/no-retained/no-exclusion sections, Completion Expectation and Interpretation Limits; preset application runs initially and on both `change` and `input`
- Feedback Boundary: `tiinex.feedback.v1` is present in Core but its current creation contract is blocked because the representative creation projection omits inherited `Observed Signal`, `Source`, and `Interpretation` requirements and Core exposes no implemented creation renderer; VS Code therefore reports `authoring is not currently qualified by Core. No artifact was written.` rather than inventing missing Feedback semantics or surfacing a raw schema-not-creatable failure
- Core Regression: full Core suite passes 186/186, including new direct-continuation and deterministic leaf-repair regressions
- VS Code Regression: full bridge suite passes 100/100 after replacing one stale implementation assertion that expected the removed whole-Workspace Parent indexing pass
- Package Integration: 4/4 package integration scenarios pass, including pointerless package manufacture, roundtrip orientation, idempotent retry/collision behavior, and extracted VSIX bundled-Core execution
- Host Build Boundary: this extracted recovery Workspace does not carry the local `@types/node` / `@types/vscode` install needed for a standalone `tsc --noEmit`; changed TypeScript surfaces were transpiled and exercised through the bridge suite, while full Windows build/live-host acceptance remains separate

## Preservation And Fidelity

- Preservation State: changes are limited to Core authoring Parent/editor-assistance mechanics, VS Code authoring orchestration/presentation, matching dist output, focused tests, and this Evidence
- Fidelity Notes: no new schema family, JSON sidecar, private authority store, or editor-specific artifact semantics were introduced
- Known Losses: Feedback creation itself remains unavailable until Core/Docs can expose one internally coherent qualified creation contract; the command is made truthful and non-destructive rather than pretending support

## Interpretation Limits

- Does Not Prove: that every historical artifact can be safely auto-rewritten, that Feedback semantics are complete, or that Windows UI timing/visual acceptance is complete without Sigma's live test
- Not Yet Used As: VSIX publication or release approval
- Must Not Be Treated As: permission to rewrite historical ancestors with dependent descendants, infer missing schema semantics in the host, or replace Core's creation/validation contracts with VS Code-owned logic
- Authority Limits: bounded local Core/extension-vscode artifact-authoring mechanics and qualification only
