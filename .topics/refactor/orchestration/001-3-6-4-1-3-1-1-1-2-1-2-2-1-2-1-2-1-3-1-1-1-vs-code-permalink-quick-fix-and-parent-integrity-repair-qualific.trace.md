# VS Code Permalink Quick Fix And Parent Integrity Repair Qualification

## Supported Claim Or Question

- Supported Claim Or Question: do live VS Code diagnostics now expose Core-qualified permalink repair actions that include explicit host-resolution evidence, and distinguish/repair a mutated Parent integrity digest at its own `Value` instead of collapsing it into the consequential self-integrity finding
- Evidence Role: qualify Sigma's second live-host diagnostics pass after the prior permalink/self-placement correction

## Provenance

- Known Source: continuation of `VS Code Live Diagnostics Runtime And Permalink Resolution Qualification`, plus Sigma's Windows evidence showing a broken Current Schema permalink with no visible latest Quick Fix and a manually corrupted Parent/Towards digest reported only as child-self mismatch
- Preservation Basis: bounded Core editor-assistance/lineage-priority changes, bounded VS Code CodeAction filtering correction, focused regression, full Core validation, full bridge suite, and package integration
- Provenance Limits: exact Windows UI rendering after this return remains Sigma-owned live acceptance; this Evidence does not make `master` semantic authority or authorize arbitrary checksum rewriting
- Semantic Authority Boundary: Core owns diagnostic severity/location and replacement bytes; VS Code exposes only Core-qualified actions, including actions whose qualification is strengthened by explicit host resolution evidence

## Evidence Material

- Material: Core lineage-integrity inspection/editor assistance plus VS Code diagnostics CodeAction projection
- Material Kind: bounded diagnostics and deterministic repair qualification
- Permalink Action Visibility: shared Core already projected broken/stale permalink replacement actions as `deterministic-shared-core+explicit-host-resolution`; the VS Code CodeAction provider previously accepted only exact `deterministic-shared-core`, hiding those otherwise qualified actions. The provider now accepts the deterministic shared-Core qualification family without widening to non-Core actions
- Broken Permalink: a proven missing exact permalink remains `ERROR`; when explicit host resolution provides a commit-pinned latest candidate, `Repair <field> permalink to latest` is now visible as a native Quick Fix
- Stale Permalink: a resolvable exact permalink whose latest candidate has different bytes remains `WARNING` and exposes `Upgrade <field> permalink to latest`; equal bytes remain clean
- Parent Integrity Ownership: when an existing Parent integrity `Value` is manually changed, lineage inspection now prioritizes `parent-target-mismatch` before the consequential `child-self-mismatch`, because the Parent relation is the more specific corrupted surface
- Parent Diagnostic Placement: `portable.lineage-integrity.parent-target-mismatch` is deterministically located on the non-self Parent integrity `Value`; the independent canonical self mismatch remains located on `Towards: self -> Value`
- Parent Repair: when the declared Parent locator already matches the exact resolved Parent and the Parent's primary self digest is verified, Core exposes `Refresh Tiinex Parent integrity and self seal`, replacing only the incorrect Parent digest and resealing the focused artifact's self integrity
- Descendant Boundary: the Parent repair action is withheld when shared lineage requalification shows loaded descendants would become inconsistent; the editor does not perform an unqualified partial cascade
- Core Qualification: focused Parent integrity regression passes and full Core validation passes 194/194 tests, portable smoke, and embedded bootstrap qualification
- VS Code Qualification: bridge suite passes 102/102 with a disposable test-only installed Core binding; canonical extension manifest/lock source remains unchanged
- Package Integration: 4/4 package integration scenarios pass

## Preservation And Fidelity

- Preservation State: changes are bounded to Core lineage-inspection/editor assistance, VS Code diagnostics filtering/dist/tests, and this Evidence
- Fidelity Notes: no host-private repair algorithm, checksum database, JSON authority sidecar, or automatic reference upgrade is introduced
- Known Losses: live GitHub availability/rate-limit behavior and Windows interaction remain host acceptance surfaces

## Interpretation Limits

- Does Not Prove: every checksum mismatch is safe to repair, `master` is authority, a stale permalink is invalid, or descendants may be silently cascaded
- Not Yet Used As: VSIX publication or remote repository mutation approval
- Must Not Be Treated As: permission to accept arbitrary Parent digest replacement without exact loaded Parent bytes, hide consequential self-integrity diagnostics, or expose non-Core host-invented Quick Fixes
