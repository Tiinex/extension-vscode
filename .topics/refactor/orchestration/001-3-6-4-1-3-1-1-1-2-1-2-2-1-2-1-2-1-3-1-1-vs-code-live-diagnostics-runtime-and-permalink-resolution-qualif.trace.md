# VS Code Live Diagnostics Runtime And Permalink Resolution Qualification

## Supported Claim Or Question

- Supported Claim Or Question: does the corrected VS Code diagnostics flow execute the exact open Local Core runtime when available, place deterministic self-integrity diagnostics from that current Core source, verify version-bearing GitHub permalinks, distinguish unresolved from stale references, and offer an explicit latest-permalink Quick Fix without treating `master` as semantic authority
- Evidence Role: qualify Sigma's live-host follow-up for diagnostic source/runtime coherence and version-bearing permalink verification without moving validator semantics into VS Code

## Provenance

- Known Source: continuation of the prior VS Code Artifact Authoring Self-Integrity, Continuity, Feedback And Conversation Qualification plus Sigma's live-host evidence showing stale self-diagnostic placement and unverified schema permalinks
- Preservation Basis: exact Core and extension-vscode source changes, focused Core tests, full Core validation, VS Code bridge qualification, package integration, and direct shared-Core CLI projection with explicit reference-resolution evidence
- Provenance Limits: final Windows rendering/network acceptance remains Sigma-owned; GitHub network availability is host evidence, not semantic authority
- Semantic Authority Boundary: VS Code resolves external bytes and supplies explicit resolution facts; shared Core alone decides diagnostic severity, source location, repair title/replacement bytes and whether a Quick Fix is exposed

## Evidence Material

- Material: Core editor assistance/CLI input, VS Code diagnostics runtime selection, GitHub permalink resolution bridge, matching dist/tests, and exact follow-up source delta
- Material Kind: bounded Core + extension-vscode diagnostics and reference-resolution implementation with deterministic qualification
- Local Core Runtime: when an open Workspace root is an exact `@tiinex/core` source checkout, diagnostics execute that root's `tools/tiinex-portable.mjs`; the bundled dependency is used only when no Local Core Workspace is present. This prevents stale bundled diagnostics from disagreeing with the visible Core source
- Self Diagnostic Placement: the current shared Core resolver anchors `integrity.c14n-v2.mismatch` and `portable.lineage-integrity.child-self-mismatch` to the primary `Towards: self` Value, outranking generic `field: Value` evidence
- Resolution Scope: host resolution is bounded to version-bearing GitHub links in `Envelope Schema`, `Parent Schema`, `Current Schema`, and the maintained c14n-v2 integrity method reference
- Exact Unresolved: a proven missing exact permalink projects `reference.permalink.unresolved` as an error; if master contains the same repository/path, Core may expose an operator-selected repair to a commit-pinned latest candidate
- Verification Unavailable: network/host inability to verify the exact target projects `reference.permalink.verification-unavailable` as a warning rather than fabricating missing authority
- Stale Reference: when the exact permalink resolves but the commit-pinned latest material discovered from `master` has different bytes, Core projects `reference.permalink.stale` as a warning and offers `Upgrade <field> permalink to latest`
- Equal Bytes: when exact and latest material have equal bytes, no stale diagnostic and no upgrade Quick Fix are projected even when commit identities differ
- No Latest Candidate: when master does not provide the file, no fake latest Quick Fix is offered; exact unresolved state remains explicit
- Latest Authority Boundary: `master` is used only to locate a candidate file revision; the Quick Fix target is the exact commit returned for that path, and no automatic mutation occurs
- Replacement Integrity: a chosen permalink Quick Fix updates only the selected version-bearing link and deterministically reseals the existing primary c14n-v2 self entry when present; ambiguous self integrity remains fail-closed
- Core CLI Qualification: direct `project-editor-assistance` projection with explicit resolution evidence returns `reference.permalink.stale` as warning on the exact Current Schema line and exposes the matching latest Quick Fix
- Core Qualification: full Core validation passes 193/193 tests plus portable smoke and embedded bootstrap qualification
- VS Code Qualification: bridge suite passes 101/101 with temporary test-only installed-Core material; the harness is removed afterward and does not alter canonical source
- Package Integration: 4/4 package integration scenarios pass

## Preservation And Fidelity

- Preservation State: changes remain bounded to Core editor-assistance projection/CLI input, extension-vscode diagnostics/runtime/reference-resolution plumbing, matching dist/tests, and this Evidence
- Fidelity Notes: no canonical JSON support artifact, reference cache database or editor-private validation semantics are introduced; temporary resolution JSON exists only for one CLI operation lifetime and is deleted afterward

## Interpretation Limits

- Does Not Prove: `master` is semantic authority, every newer revision should be accepted, offline verification failure means a permalink is broken, or every external Markdown link is version-bearing Tiinex authority
- Not Yet Used As: VSIX publication or remote repository mutation approval

- Authority Limits: bounded diagnostics runtime coherence, explicit external resolution evidence, shared-Core severity/location/Quick Fix projection, and return for source reconciliation only
