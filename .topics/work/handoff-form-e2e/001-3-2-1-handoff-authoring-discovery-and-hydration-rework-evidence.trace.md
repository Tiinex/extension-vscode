# Handoff Authoring Discovery And Hydration Rework Evidence

## Supported Claim Or Question

- Supported Claim Or Question: whether the latest Sigma Handoff-form REWORK can be repaired without Handoff-specific discovery, while preserving embedded Tiinex Transition material, Workspace-representation boundaries, Party authority qualification, and independent authoring UI progress.
- Evidence Role: bounded human-return plus implementation/regression evidence for the next Handoff-form rerun.
- Target Artifact: Sigma Handoff Form Ergonomics Re-Review Handoff.
- Review Context: the silent Sigma rerun showed Outgoing creation refreshing correctly, but the open Handoff form remained stuck on `Core authoring candidates loading...` and `Core transition discovery loading...`; From/To smart controls and Transition presets therefore never became usable, and Attach to Outgoing stayed disabled after Outgoing was created later.

## Provenance

- Known Source: latest Sigma silent screen recording and direct follow-up, current carried Core/Native/VS Code Workspaces, current embedded Handoff Transition companions, focused Core regression, cold multi-root operator-context probes, and pure/static VS Code host probes.
- Preservation Basis: implementation bytes and regression sources are carried in Core/VS Code; Transition source modes and Party projections come from Core operations rather than UI reconstruction.
- Provenance Limits: this sandbox does not replace Sigma's real locked-dependency VS Code runtime; final UI timing/ergonomics and package preview remain a human gate.

## Evidence Material

- Material: `.topics`-bounded portable input traversal, multi-root operator-context Party index, embedded-plus-Workspace Transition discovery, independent authoring hydration lanes, webview readiness replay, live host-action state, and Incoming icon differentiation.
- Material Kind: human rework evidence plus bounded implementation and regression evidence.
- Human Rework: Transition presets and From/To selectors were still unusable because their discovery/hydration never reached the visible form; Attach to Outgoing remained a stale snapshot when Outgoing was created after the form opened. Sigma additionally requested Reject use a trash icon so it is visually distinct from Close.
- Workspace Discovery Boundary: semantic operator projections now ask Node portable input to traverse `.topics` only for operator-context / endpoint / Workspace-source/session-role discovery. Paths remain Workspace-relative `.topics/...`; repo `src`, build outputs, assets, and unrelated files are not traversed by that semantic discovery path.
- Multi-Root Party Index: one explicit multi-root `project-operator-context` projection now carries top-level Workspace sources, exact Role/Party endpoints, readable authoring-assist endpoints, and current Role endpoints. VS Code reuses that projection through a short-lived normalized-root cache instead of starting one endpoint projection per Workspace for each consumer.
- Real Multi-Root Probe: 17 presented roots produced Core status `ready`, zero findings, 20 qualified Workspace representations, 1 exact endpoint, 22 authoring-assist endpoints, and 1 exact semantic participant in about 5.08 seconds cold in this sandbox. The host cache allows Local Workspace selection and Party-reference authoring to reuse the same projection during one authoring interaction.
- Embedded Transition Boundary: Core Transition neighborhood already composes native schema/companion material through `portable-composed-schema-content`; external discovery is additive. VS Code now passes only presented `.topics` roots as external semantic material while Core's embedded/native Transition material remains included independently.
- Transition Fast-Lane Probe: current Workspace `.topics` plus embedded Tiinex material projected cleanly in about 1.47 seconds and exposed the three Handoff authoring presets `Discuss / review`, `Open bounded conversation / brainstorm`, and `Perform bounded work`, each from embedded `portable-composed-schema-content` material.
- Independent Hydration: Party-reference discovery, fast embedded/local Transition discovery, enriched multi-Workspace Transition discovery, and live host-action availability are independent state slices. Party discovery cannot block Transition presets; Transition discovery failure cannot remove Manual authoring.
- Webview Readiness: the authoring webview now sends an explicit `authoring-ready` handshake; the host retains the latest Party/Transition/host-state slices and replays them after readiness. The host registers the webview message receiver before assigning HTML, and the ready callback receives the concrete panel reference, closing the previous fast-result/message-listener race.
- Live Outgoing State: open authoring panels receive `authoring-host-state` updates from UI-context refresh. A Handoff form opened before Outgoing exists can therefore enable Attach to Outgoing when that Workspace later becomes selected, without closing/reopening the form.
- Party Authority Boundary: exact-qualified Party/Role choices preserve exact kind and reference. Readable authoring-assist material remains label-only and uses schema-declared `unknown` where available rather than manufacturing Role/Identity authority.
- Incoming Review Presentation: Reject now uses `$(trash)`, while Close remains `$(close)` and Accept remains `$(check)`. Existing post-Replace exact-state gating and Reject modal confirmation remain intact.
- Focused Core Regression: 74/74 tests pass with `TERM=xterm`, including `.topics` include-prefix traversal, multi-root operator-context boundary, Handoff structured creation, generic creation, authoring Parent, Transition, Handoff Package V1, and participant projection coverage.
- Host Source Verification: all touched TypeScript surfaces transpile without syntax diagnostics; pure Party/preset/Incoming helpers pass; static wiring verifies independent authoring state messages, no Party/Transition `Promise.all` coupling, live host-state hooks, ready-listener ordering, and distinct Reject/Close icons.
