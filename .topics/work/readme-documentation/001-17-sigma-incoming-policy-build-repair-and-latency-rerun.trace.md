## Transfers

- windows-build-after-replace
  - Transfer Kind: work
  - Description: Receive the single complete Handoff Package through Tiinex Incoming, confirm exact Workspace mapping, and Replace the modified VS Code Workspace. Build normally using `npm run dev:build:local` and reload. Ensure the prior TS2367 diagnostic in `src/operatorTrees.ts` is gone. Report any new compile diagnostic precisely; do not use a detached patch unless the extension cannot recover through Incoming Replace plus build/reload.
  - Controlling Artifact: [VS Code README And Documentation Consolidation](001-vs-code-readme-and-documentation-consolidation.trace.md)
  - Boundary: local Windows build/reload acceptance; no remote mutation or release.

- resume-incoming-first-preview-latency
  - Transfer Kind: work
  - Description: After the compiled extension reloads, retest Send to Incoming from the same repositories and package size. Measure time to first visible qualified Handoff Markdown separately from Core orientation and local review comparison. Compare against reported ~1m20s current and prior 3–6s experience. Verify that preview can show before the independent local review finishes; Accept/Reject must still wait for fresh exact review and Close must not resurrect removed packages. Report timing and diagnostic logs if still slow. Retain previous Outgoing Blank/Parent, package transport, basic Evidence Create/reopen gates where unresolved.
  - Controlling Artifact: [VS Code README And Documentation Consolidation](001-vs-code-readme-and-documentation-consolidation.trace.md)
  - Boundary: host Windows acceptance not yet established.
