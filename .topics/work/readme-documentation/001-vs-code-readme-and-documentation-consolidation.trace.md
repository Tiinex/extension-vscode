# VS Code README And Documentation Consolidation

## Objective

Make `README.md` sufficient for normal Tiinex VS Code use while moving durable deep documentation into qualified `.topics` artifacts and retiring the repository `docs/` directory without duplicating semantic truth.

## Done Criteria

- a normal extension user can install, orient, author/receive Handoffs, use Incoming/Outgoing/Transport, understand Operator Party and find the important settings from `README.md` alone
- README uses a small set of short visual demonstrations where motion materially improves comprehension
- retained deep guidance is represented by appropriate Tiinex artifacts rather than copied into a parallel `docs/` knowledge tree
- user-facing extension use and Tiinex-internal extension development remain distinguishable reusable processes
- obsolete or duplicated `docs/` material is removed rather than mechanically relocated
- Viewer/repository discovery can find the retained process, troubleshooting, use-case and presentation material from `.topics`
- Marketplace/release automation work remains deferred until README/media/documentation consolidation is reviewed

## Scope

- README information architecture and content
- inventory/reduction of current `docs/`
- VS Code-specific Process, troubleshooting/use-case, and presentation material only where a real artifact is warranted
- four bounded README media captures in the first capture tranche
- no extension feature changes unless documentation exposes an actual product defect
- no Marketplace publication, credential setup, release automation activation, commit, or push in this Task tranche

## Dependencies

- VS Code functional/ergonomic acceptance returned PASS in the carried `030-1-1` checkpoint
- canonical Role/Organization/process/schema material continues to live in its owning Workspace (for example Business or Native) rather than being duplicated into VS Code solely for documentation navigation
- Sigma supplies the requested real-host capture material; Anchor owns selection, companion authoring, README composition and `docs/` reduction afterward
