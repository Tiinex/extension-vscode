## Objective

Converge the existing qualified Core, Native, VS Code, Business and Interop work on a release-quality VS Code extension without duplicate host semantics, loose patches, or using Sigma as a live debugger. This is a coordination/acceptance gate, not an alternative feature owner.

## Done Criteria

- Core Move/Rebase dry-run/Apply covers a qualified ordinary artifact and explicitly selected ordinary assets, planned reference rewrites, drift/collision safeguards and recovery. The host only presents Core plans and approvals.
- Evidence child-of-Evidence works for qualified newly created Parents or returns an exact explained authority blocker; no host bypass of Core qualification.
- Native repeated Evidence Material remains the single schema truth; each Attach to Form receives its own editable material entry and conservative filytype-based Material Kind *suggestion* (never unreviewed semantic fact). Preview/Create/reopen roundtrip preserves names, provenance and references. Planned file moves are labelled pending until atomic commit.
- Save as Transition from a partially completed Evidence seeds a separate native/Core-qualified Transition Definition form with actual mapped partial values. Preview/Create/reopen and Core discovery/companion qualification prove retention. Missing mappings remain visibly unknown, never silently dropped.
- Portable Core agent capabilities and Role projection are delivered by the existing owner Tasks into VS Code native tool/skill/agent host adapters; protect user-edited frontmatter and reject duplicate MCP semantics and invented Role-to-permissions.
- Bootstrap/role/entry/target/recipient and cross-workspace grounding are cold-rehearsed independently with negative cases and no holder inference from package or conversation.
- Normal changes and recovery are carried through canonical Tiinex-manufactured package continuations. Anchor→Anchor recovery at stable checkpoints. Sigma gets one separate bounded final human acceptance Handoff with exact instructions *inside* the package and a small set of on-screen steps; no dependency on chat history.
- Clean dependency-backed VS Code compilation, Core/Native/host tests, end-to-end browser and clean Windows VSIX acceptance pass before declaring release readiness. Then finish README/media/docs consolidation and apply the existing Marketplace release gate. Do not publish before explicit release authorization.
