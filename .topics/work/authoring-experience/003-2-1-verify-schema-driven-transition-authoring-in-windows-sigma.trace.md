# Verify Schema-Driven Transition Authoring In Windows Sigma

## Objective

Accept or reject the real installed VS Code extension's Evidence-v1 Save as Transition journey, nested repeatable Transition Definition, Schema Transition Companion, and existing Move/Rebase/transport interoperability after Core and Chromium regression. Do not require operator investigation of unrelated bugs or raw Core setup.

## Done Criteria

- Windows host runs normal qualified Incoming → Replace → extension build → Reload. If build/activation fails, fail gate immediately with exact output. No claim Linux/Node transpilation is equivalent to Windows TypeScript build.
- New Evidence form preserves at least two separately described Material records with Attach to Form, per-material fields, Preview and Create; parent Evidence → Evidence is still valid. User may test using disposable sample files.
- From an intentionally unfinished Evidence, Save as Transition opens **a separate Transition Definition form**, does not create Evidence, never guesses roles or conditions, and defaults new Definition destination beneath the planned artifact working directory's `.transitions`. No movement of assets occurs merely by opening the form.
- The Definition form has actual Core-authorized nested repeatable records for Lifecycle Effects/Parent Effects and Destination Bindings/Output Placements, add/remove/none operations, per-entry names/fields, meaningful placeholders, human guidance and collapsed provenance. Preview/Create yields a valid separate Markdown artifact; Schema Transition Companion is independently authorable with explicit safe attachment where qualifying source exists.
- A Transition Definition without qualified schema-companion attachment and generation defaults must **not** automatically become an Evidence preset or executable command. Missing native Evidence-specific preset is a separate feature limitation, not a hidden automatic success.
- Qualified Move/Rebase keeps existing source hash/preflight safeguards for Tiinex artifact references and supported ordinary file path references, fails closed for unsupported formats and never silently follows outside-Workspace paths. Confirm host panel access distinction for Copilot, Incoming review and Outgoing package transport.
- Reopened Markdown is schema validated without a fabricated remote GitHub source link; any local unpublished schema authority is accurately shown. No form accepts stale, colliding, or unbound fields as if qualified by Core.
- Sigma returns one PASS/FAIL with build result, 1 silent video and exact first failure if any. This Task is complete only after real Windows results are assessed by Anchor, not automatically accepted by local Node tests.

## Scope

Host integration and one coherent Windows end-to-end accept/reject session; portable Core/Native semantics remain unchanged. Move/Rebase tool format limits remain fail closed and Native Surface CLI/LLM parity continues under a separate fork.
