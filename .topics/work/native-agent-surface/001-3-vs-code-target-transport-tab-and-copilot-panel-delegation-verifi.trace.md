# VS Code Target Transport Tab and Copilot Panel Delegation Verification

## Supported Claim Or Question

- Supported Claim Or Question: Can VS Code project and display transport guidance in a Markdown tab using Core's real receipt, while leaving the human panel and ordinary Core authoring independent of the three Copilot panel delegation levels?
- Evidence Role: source/model regression evidence for the VS Code owner Task, subject to installed Windows acceptance.

## Provenance

- Known Source: VS Code source `src/vscode/transportCompletionPresentation.ts`, `src/core/copilotPanelAccess.ts`, `src/vscode/copilotPanelDelegation.ts`, `src/tiinex/bootstrap.ts`, `src/operatorTrees.ts`, package configuration, tests under `test/transport-completion-source.test.cjs` and `src/core/copilotPanelAccess.test.cjs`.
- Preservation Basis: exact TypeScript source, package setting and test scripts carried with the local VS Code Workspace; actual Core projection consumed over the portable CLI.
- Provenance Limits: This extension build lacks locally installed TypeScript node/vscode type-definition packages; full `tsc` and Windows runtime acceptance remain open.

## Evidence Material

- target-entry
  - Material: [VS Code Copilot Execution Target](../../.entries/where/vscode-copilot/001-vs-code-copilot-execution-target.trace.md)
  - Material Kind: schema-authorized VS Code-owned Target Entry
  - Description: Current `tiinex.entry.target.v1` source is discoverable by Core in an explicit carried Workspace, preserves What's original semantics and adds host-specific attachment, role and clipboard/Markdown interaction steps.
  - Material Limits: Availability of that material does not activate a Process or grant Copilot transport authority.
- markdown-presentation
  - Material: Core projected transport Markdown opens as a fresh unsaved document tab; actual VS Code clipboard status is labelled separately. Exact projected clipboard bytes and canonical carrier filename are verified before presentation.
  - Material Kind: host renderer behavioral test
  - Description: Reuses one presenter for ordinary pack, Guided Entry, route copy, pointerless and bootstrap replacement paths, without injecting a second transport grammar into the tree controller.
  - Material Limits: Source harness is not an installed Windows extension session.
- restricted-panel-tools
  - Material: `None`, `Pack and Transport`, `Inspect, Unpack, Pack and Transport` policy is evaluated only by the future agent adapter; unknown and destructive operator actions are denied even at the highest level.
  - Material Kind: host delegation policy regression
  - Description: Default None does not touch artifact creation, schema discovery, grounding, regular CLI or human-operated panel commands.
  - Material Limits: No native Copilot agent tool has been registered yet; the policy is implemented and tested, but native agent invocation enforcement still belongs to the separate Surface gate.

## Preservation And Fidelity

- Preservation State: VS Code owner code/tests and valid Target Entry bytes retained.
- Fidelity Notes: Clipboard content is never reconstructed by the UI; the tab reports actual host copy status. `release:audit` passes with zero warnings/errors.
- Known Losses: Complete VS Code TypeScript build blocked by unavailable npm type packages in this runtime; installed Local/Copilot Agent Host tests still require Sigma.

## Interpretation Limits

- Does Not Prove: that all Copilot harnesses honor hooks, that unrestricted terminal agents are isolated, that operator transport was performed or that a copied Handoff automatically changes an agent's Role.
- Not Yet Used As: final Sigma Windows acceptance.
- Must Not Be Treated As: permission to grant Incoming Replace, Git reset, delete or remote-send to Copilot through a panel access setting.
